# 第 13 题：混合精度训练（Mixed Precision Training）

## 一、混合精度混合了什么？

按操作和状态选择精度：矩阵计算、部分激活可使用 FP16/BF16，敏感操作和累加常保留 FP32，优化器及主权重的具体存储精度由训练方案决定。PyTorch autocast 是逐算子选择计算类型，不等于永久把所有模型参数转成半精度。

目标是降低部分存储和带宽成本、利用硬件低精度算力，同时控制误差。总显存不一定减半，速度不一定翻倍，效果也需要验证。

## 二、FP32、FP16、BF16 的数值区别

- FP32：1 位符号、8 位指数、23 位显式尾数，最大有限值约 3.40×10^38。
- FP16：1/5/10，最大有限值 65504；最小正正常数 2^-14≈6.10×10^-5，最小正次正规数 2^-24≈5.96×10^-8。
- BF16：1/8/7，指数范围接近 FP32，最大有限值约 3.39×10^38，但尾数比 FP16 更少，精度更粗。

**FP16 小于 6×10^-5 不会一律变 0。**进入次正规数范围后有效精度下降；更小的值会舍入到 0，硬件/算子也可能 flush-to-zero。BF16 范围接近 FP32，不代表数值精度相同，FP32 转 BF16 通常还涉及舍入，不能简单理解为永远截断低 16 位。

不同模型的梯度范围不同，不能把“所有梯度都在某个固定区间”或“尾数精度对训练不重要”作为普遍结论。

## 三、Loss Scaling：先放大梯度，再还原

对 loss 乘正数 S 再反向：

$$
\nabla_\theta(SL)=S\nabla_\theta L
$$

更新前将梯度除以 S。精确算术中与原梯度等价；有限精度下的目的就是减少下溢，因此不能说结果逐 bit 完全相同，或“无条件数值安全”。它也不能修复已经发生在前向中的溢出。

例子：梯度 g=10^-8 可能在 FP16 中舍入为 0；取 S=1024，反向传播中尺度为 1.024×10^-5，落入可表示的次正规范围，再在较高精度的梯度处理中还原，能减少丢失。更大 S 也会增加溢出风险。

典型流程：autocast 前向 → 缩放 loss → backward → unscale 梯度 → 梯度裁剪（如需要）→ 检查并执行 optimizer step → 更新 scale。实际 GradScaler 会组织 unscale 与非有限值检查；精度和副本安排依具体框架。

必须先 unscale 再按原阈值裁剪，否则裁剪的是被放大的梯度，改变有效更新。

## 四、动态缩放与梯度累积

检测到 inf/nan 时通常跳过当前 optimizer step 并降低 scale；连续一段时间没有非有限值后再尝试增大 scale。**一般不会自动用同一批数据重跑一次。**scale 也没有必须大于 1 的保证，取决于模型的可表示范围。

梯度累积期间，同一有效 batch 内应保持 scale 一致，在累积完成后统一 unscale、裁剪和更新。若每个 micro-batch 的 loss 都是均值且样本数一致，可先除以累积步数；不同 token 数或不同 loss reduction 要按实际权重归一化。

## 五、BF16 与 FP16 如何选择？

FP16 训练通常配合梯度缩放；BF16 因指数范围较宽通常不需要。但 BF16 仍会舍入、溢出并有精度问题，不能保证所有模型都稳定。要结合硬件和算子支持、模型数值范围、稳定性与吞吐测试选择。

推理没有训练式反向传播，不能把 loss scaling 当成推理选择 BF16 的理由；应比较范围、精度、kernel 和硬件支持。

## 六、面试答法与自测

混合精度按操作和状态使用不同精度，以低精度加速和节省部分内存，以 FP32 等较高精度维护敏感计算。FP16 范围较窄，通常通过 loss scaling 减少梯度下溢，更新前还原；BF16 范围接近 FP32但尾数更少，通常无需缩放。收益和稳定性都必须实测。

自测：6×10^-5 是 FP16 正常数边界，不是统一归零阈值；裁剪在 unscale 之后；动态缩放出现 inf 时跳过更新，不默认重试当前 batch；混合精度不保证总显存减半。
