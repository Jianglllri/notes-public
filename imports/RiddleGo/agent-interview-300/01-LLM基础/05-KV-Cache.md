# 第 5 题：KV Cache 的原理与在自回归生成中的作用

### 它们是什么

Prefill（预填充）是处理已经给定的输入 token，为后续生成建立每层需要的缓存状态；最后一个输入位置的模型输出通常还用于采样第一个回答 token。Decode（增量解码）是利用缓存和最新已生成 token，继续产生下一个 token，直到遇到停止条件。它们通常属于同一个自回归模型的两个运行阶段，不是分别用两个模型，也不要和 Encoder-Decoder 模型的编码器/解码器结构混淆。

Token 是分词器的单位，不一定等于一个汉字、单词或字节。这里的 Decode 指模型增量生成，与 tokenizer.decode 把 token IDs 转成文字是两个层面的“解码”。

设输入为 x1…xL，输出为 y1…yT，自回归概率分解为：p(y1…yT|x)=∏t p(yt|x,y1…y(t-1))。这解释了为什么生成 yt 前需要确定此前输出，而输入 x1…xL 本来就全部已知。

### 一条请求怎样走完

用户提交一段 1000-token 材料，要求输出约 100 token 的摘要：先将文本分词；Prefill 在各层处理这 1000 个已知位置，保存所需 KV；最后输入位置产生 y1 的分布并采样；随后把 y1 作为新增位置前向，得到 y2；再处理 y2 得到 y3，直到结束。

因此普通非推测路径中，若最终恰好输出 100 个 token，而且 y1 由末块 Prefill 产生，后面通常还需 99 次增量生成推进。是否额外采样 EOS、怎样统计输出数依具体实现，不能无条件说“输出 100 token 就一定有 100 次 Decode”。

注意细节：刚采样出的 y1 尚未作为输入通过各层，其 KV 通常在下一次增量前向处理 y1 时形成。采样完成不等于该 token 的所有 KV 已写入。DeepInfer 的 token 与 cache 长度账本正是需要区分这些状态。

### 为什么 Prefill 可以并行，Decode 不能把未来全部一次算完

Prefill 的“并行”指同一层中多个已知 token 位置可以并行执行矩阵运算。因果 mask 让位置 i 只读取到 i 为止的有效上下文，不意味着必须先把 x1 跑完整个网络，再跑 x2。层与层仍有依赖，并非所有层也可随意同时计算。

普通 Decode 的未来 token 内容尚未确定。产生 y2 需要已选出的 y1；因此单请求沿生成时间存在串行依赖。不过同一 token 内部的矩阵、注意力头、专家以及不同用户的请求可以并行。推测解码则先提出候选再批量验证，能一次提交多个 token，但没有取消自回归的条件依赖。

### KV cache 到底缓存什么、节省什么

普通注意力在某一层对输入表示 H 做 Q=HWq、K=HWk、V=HWv，并计算 Attention(Q,K,V)=softmax(QK^T/√d + causal_mask)V。Q 可理解为当前位置要查询什么，K 用于匹配，V 提供被聚合的信息；这是帮助理解的类比，不是文字被原样存进数据库。

因果模型中，旧位置的表示不依赖未来新 token，所以在权重、位置和输入前缀不变时，其 K/V 可以复用。增量阶段只计算新位置需要的表示和 K/V，并让新 Q 访问允许的历史 K/V。

KV cache 省掉的是重复计算旧位置的中间状态；没有让模型跳过全部历史，也没有省掉新 token 通过各层和权重计算。全注意力 Decode 仍需读取历史 KV。不同请求的 KV 通常不能随意共享，除非有匹配前缀等明确复用机制。

普通层式 KV 缓存粗略容量为 2 × 层数 × KV头数 × 每头维度 × 每元素字节数 × 总缓存token数；2 表示 K 与 V。教学参数：32层、8个KV头、head_dim=128、FP16，得到每token 128 KiB，8192 token 约1 GiB，32条这样的序列仅KV就约32 GiB，不含权重、激活、碎片等。这不是 DeepInfer 实际显存估算，MLA、压缩KV、SWA等会改变布局和容量。


## 复杂度与优化边界

KV cache 避免旧位置重复前向，新增位置的 K/V 投影成本对历史长度是 O(1)，但单步全注意力仍需读取 S 个位置的 KV，注意力项为 O(Sd)。不能把“新增 K/V 计算 O(1)”写成“整个解码 O(1)”。

输入长度 L、增量推进 T 步，注意力累计约 O((TL+T²)d)。首次 prefill 仍需处理提示词；普通 KV cache 主要加速后续 decode，只有确实复用已缓存前缀等机制才可能省掉相应 prefill。

通常不缓存历史 Q，因为下一步只需要新位置的 Q 查询历史 K/V，不需要重新计算旧位置的注意力输出。

- PagedAttention：改进块式分配、碎片控制和共享管理，不自动减少每个 token 的原始 KV 数据量。
- GQA/MQA：减少 KV 头数，见第 18 题。
- KV 量化：降低每元素字节数，需要评估误差与 kernel 支持。
- 滑窗/淘汰：限制保留范围，会改变可访问的历史信息。
- 前缀复用：要求模型、输入前缀、位置等缓存条件一致，不能随意跨请求共享。

## 为什么 prefill 常偏计算、decode 常偏访存？

线性层 X[M,d]W[d,f] 约需 2Mdf FLOPs。若只计权重读取一次的流量 bdf 字节，则算术强度约 2M/b FLOPs/byte。FP16/BF16 的 b=2，此简化模型下强度约为 M。

M 表示本轮新计算位置数，不是历史长度：1000-token prefill 约 M=1000；单请求普通 decode 约 M=1；32 条 decode 合批约 M=32。合批让更多位置复用同一份权重，改善利用率；权重通常驻留显存，不是每步从磁盘加载。

以 d=f=4096 为例，一个线性层 M=1 时约 33.6 MFLOPs，M=32 时约 1.07 GFLOPs。FLOPs 是工作量，FLOP/s 是速率。粗略性能下界 T≥max(F/P,B/BW)，还要计入 KV、激活、通信、同步等；不能从这个简化式断言所有 decode 都访存受限，或 batch 增大耗时不变。长上下文 decode 可能由 KV 读取主导。

## 面试答法与自测

KV cache 利用因果模型中旧位置不受未来 token 影响的性质，逐层缓存历史 K/V。新位置只算自己的前向，并用新 Q 查询历史。它节省重复计算，以缓存显存为代价；单步全注意力仍随上下文长度线性增长。

自测：32 层、8 个 KV 头、head_dim=128、每元素 2 字节，每 token 为 131072 字节=128 KiB，8192 token 为 1 GiB。最后一个提示词位置采样出的 y1，通常在下一次把 y1 输入模型时才生成它的 KV。
