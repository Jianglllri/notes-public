# 第 27 题：Agent 中的记忆机制——短期记忆 vs 长期记忆

## 一、记忆究竟在哪里？

短期记忆服务当前会话或任务，长期记忆支持跨会话复用。模型本次推理能直接利用的是当前上下文及参数中已有的知识；外部数据库里的信息必须被读取、检索并放入上下文，才能影响这次回答。

外部记忆持续更新不等于模型权重持续训练。它可以改善个性化和后续行为，但不应直接称为参数层面的持续学习。会话状态也可以持久化，因此短期/长期主要是用途和生命周期的区别，不只是“在内存还是在磁盘”。

## 二、短期记忆怎么实现？

- 滑动窗口：保留最近若干轮或 token，简单但会丢失较早信息。
- 摘要压缩：旧对话整理成摘要，结合近期原文；摘要可能漏掉限制条件，应保留来源。
- 结构化任务状态：目标、已完成步骤、待办、工具调用及观察结果，按需注入，不要求保存模型隐藏推理过程。

例如“正在排查数据库连接失败，已验证 DNS，下一步查权限”属于工作状态。实际恢复任务时，工具结果还可能过期，需要重新检查。

## 三、贯穿例子：下一次会话如何继续学习？

假设用户曾说：“我在准备推理岗位面试；讲解先给例子再讲公式；已学 KV Cache，接下来学 GQA。”新会话只问“今天接着学什么？”

系统可以分别保存：

1. 长期目标：准备推理岗位面试。
2. 讲解偏好：例子优先。
3. 学习进度：KV Cache 已学习。
4. 下一步计划：GQA。

读取这些信息后，模型才能有依据地建议“继续学 GQA，先用 Q 头和 KV 头的数量计算显存”。这不是模型天然记得上次会话，而是应用把必要记忆交给了模型。

## 四、向量记忆：根据语义找相关片段

### 写入流程

对话或工具结果 → 提取值得复用的事实/事件 → 去重并检查冲突 → 保存原文与元数据 → embedding → 建立向量索引。

原文“用户已学习 KV Cache，计划学习 GQA”与其 embedding 一起存储。元数据至少包括 user_id、类型、来源消息、记录时间、有效状态；需要时添加适用范围、有效起止时间和是否为推断。

**向量用于召回，检索得到的文字用于构建上下文。**普通文本 prompt 不是直接放入一串 embedding 数字。

### 读取流程

“今天接着学什么”比较模糊，可结合当前任务改写为“检索用户最近学习进度和下一步计划”。先按用户、权限、状态过滤，再召回、重排、去重，在 token 预算内挑选必要原文或摘要。

优点是措辞不同也能匹配，例如“求职复习”和“面试准备”。但相似不等于真实、有效或最新：“喜欢长回答”和“不喜欢长回答”可能都很相似；时间、否定和状态变化必须另行处理。

稳定偏好可以按用户 ID 直接读取，不必所有记忆都走向量检索。Top-k 只是候选选择方法，不应成为完整的记忆正确性策略。

## 五、结构化存储与图谱：明确实体、关系和状态

简单偏好与进度可以存关系表或 JSON：用户的目标岗位、讲解顺序、已完成课程、下一个知识点。

图结构可以表达：用户→计划学习→GQA；GQA→前置知识→多头注意力；用户→已学习→多头注意力。随后查询“计划里哪些内容已满足前置条件”。图谱适合关系链和多跳查询，但简单偏好不一定值得引入图数据库。

抽取时必须保留语气与时间：“我可能下个月学 CUDA”是带不确定性的未来计划，不是“已学习 CUDA”。应区分用户明确陈述、系统推断、计划、已完成事实和失效记录。

## 六、外部业务数据库：查询权威当前状态

向量库、图谱、关系库不是完全互斥的类别：同一个数据库也可能同时支持结构字段、向量搜索和关系查询。

这里强调业务数据库的角色：订单状态、账户配置、课程完成记录、项目进度等需要精确查询。旧对话说“还没学 GQA”，平台却记录昨天已完成，那么回答学习安排时要核对当前状态，不能只依赖旧对话。

对话记忆保留“用户过去说过什么”；权威数据源提供“系统当前确认什么”。容易变化的状态适合按需查工具/API，非结构化经历和背景适合检索。权威来源也可能有延迟，应记录更新时间和数据出处。

## 七、MemGPT：管理有限工作区与外部记忆

MemGPT 借鉴分层存储，用工具操作和控制流程在有限上下文与外部记忆之间搬运信息。它的重点不仅是检索，还包括什么时候读、写、保留或替换工作区中的内容。

例如把稳定讲解偏好长期保存，旧对话离开窗口后，在新任务里再调入；当前任务的细节留在工作区，大量历史放外部。它没有把底层模型的注意力窗口变成无限，也不保证信息像普通内存读写那样无损、精确恢复。[MemGPT 原论文](https://arxiv.org/abs/2310.08560)

## 八、长期记忆必须有完整生命周期

### 写入：判断复用价值与适用范围

“以后讲技术都先举例”可能是稳定偏好；“今天赶时间，短一点”应优先作为当前会话约束。不要把助手自己的猜测或未经验证的工具结果自动升级为用户事实。

### 读取：找对用户、任务、时间和证据

先做身份与权限过滤，再考虑相关性、时效、重要性和可信来源。记忆是参考数据，不应自动覆盖当前用户明确指令，更不应把记忆中的指令文本当成系统指令执行。

### 更新：处理冲突和历史

旧目标“准备后端面试”与新目标“转向推理岗位”应更新当前值，同时保留必要历史。“工作沟通要简短”和“技术学习要详细”则是不同范围的偏好，可以同时存在；不能机械地最后一句覆盖所有旧记录。

### 遗忘：沿来源删除派生内容

删除原对话后，还应处理对应摘要、向量条目、缓存和由它抽取的偏好；否则可能在下一轮检索或同步时重新出现。用 source_id、derived_from 和删除标记追踪来源，按政策清理备份，并防止旧副本重新导入。

## 九、与 RAG、长上下文、微调的区别

- RAG 强调检索外部证据支持回答；长期记忆可以复用 RAG 技术，但增加用户、经历和状态的生命周期管理。
- 长上下文增大单次可读取内容，不自动提供跨会话存储、更新与遗忘。
- 微调或持续训练修改模型参数；外部记忆通常修改数据，不修改模型权重。
- KV cache 主要复用一次自回归计算中的中间张量，不等于跨会话的语义长期记忆。

## 十、面试一分钟回答

Agent 的短期记忆维护当前对话和任务状态，长期记忆跨会话保存偏好、经历和重要状态。非结构化经历适合向量检索，明确的属性适合关系表，复杂关系可用图谱，实时事实优先查权威业务系统。MemGPT 强调分层管理，在有限上下文与外部存储之间按需读写。难点不只是存储，还包括提取、检索、冲突更新、来源追踪、权限和删除传播。这里的持续积累通常不更新模型权重。
