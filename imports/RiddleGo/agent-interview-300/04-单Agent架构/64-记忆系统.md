# 第 64 题：Agent 的记忆系统设计——向量库、知识图谱、数据库

## 一、先分职责，不要先选向量库

概念及贯穿例子见第 27 题。本题侧重落地：写什么、怎样查、谁说了算、如何更新删除，以及如何证明记忆有用。

推荐从结构化事实主记录开始：关系库/文档库维护用户、来源、状态和版本；向量索引负责语义候选召回；关系查询频繁且复杂时才增加图谱。它们是能力组合，不是必须部署三套独立数据库；支持向量扩展的关系数据库也可以承担多种角色。

## 二、记忆记录需要哪些字段？

教学字段示例：

```json
{
  "id": "memory_17",
  "user_id": "user_123",
  "kind": "preference",
  "content": "技术学习时先看计算例子，再看公式",
  "scope": "technical_learning",
  "source_id": "message_456",
  "provenance": "user_explicit",
  "status": "active",
  "version": 2
}
```

另按需增加 observed_at、valid_from/valid_to、derived_from、supersedes、embedding_version、expires_at。来源可信度与模型置信度是不同维度，不能用模型高置信度代替事实证据。

事实主记录保存正文与生命周期；向量索引可由主记录重建。图关系也需来源和有效时间，避免关系抽错后无法追溯。

## 三、写入链路

1. 收集用户陈述或可信工具结果，保留原始证据。
2. 提取候选：事实、偏好、事件、计划分别标注，不混为一类。
3. 判断是否值得长期保留，并识别当前会话约束。
4. 在相同用户和范围内寻找近似重复、冲突和需要替代的旧条目。
5. 通过事务或版本检查更新主记录，再可靠地更新索引。

可以用 outbox/event 队列重试索引更新；读取时再核验主记录有效状态，避免索引尚未删除时把旧内容返回。更新应幂等，重复处理同一消息不应生成多份事实。

## 四、读取链路

当前问题与任务状态 → 构造检索意图 → 权限、用户、时间范围过滤 → 精确查找/关键词与向量召回 → 重排 → 冲突与来源检查 → token 预算内构建上下文。

不必把所有记忆做成一个全局 Top-k。稳定偏好可精确读取；历史经历可语义检索；当前订单、配额或课程完成情况查权威业务接口。

检索内容保留来源与日期；把它视为证据而不是更高优先级的指令。查不到就说明缺少记录，不应该把模糊相似片段当成确定往事。

## 五、三种存储的适用边界

向量检索适合自然语言的语义召回，但不能独立保证事实正确、时间最新、否定一致和精确状态。图谱适合关系路径和依赖查询，成本在实体消歧、关系抽取与更新。关系/文档数据库适合精确键值、事务、审计和权限；它也可以扩展语义搜索，不应绝对说传统数据库不能检索向量。

同一系统可以保存“用户曾说还没学 GQA”的历史事件，同时把当前进度更新成“已完成”；两者并不矛盾，因为时间与语义不同。

## 六、删除为什么会“复活”？

常见原因：只删 UI 记录，没删向量；删原文没删摘要；同步仍有旧副本；后台作业重新抽取了相同内容；缓存命中旧值。

处理要覆盖主记录、派生摘要、索引、缓存及同步来源。先标记删除版本并阻止读取，再完成物理清理；需要删除时也记录必要 tombstone 防止旧同步覆盖。备份保留与清除按既定政策处理，不把备份恢复悄悄当成用户重新授权记忆。

验证用例：删除偏好后，刷新、重启、重新检索和同步均不应再次返回；更新目标后，旧目标不应作为当前目标；一个用户的检索不能返回另一个用户的记忆。

## 七、Jev 等判断模型可以接在哪里？

它们可以辅助判断“这是稳定偏好吗”“新旧陈述是否冲突”“这个候选是否相关”，但数据库持久化、访问控制、版本规则和执行仍由应用负责。

TypeSafe 官方的简单记忆示例，用 Noul 判断信息是否值得保存，再把用户历史注入后续 state；示例使用 Python dict，是演示机制，并不自动具备生产级持久化、删除传播、检索或冲突管理。其演示阈值不能当成通用标准。[官方记忆示例](https://docs.typesafe.ai/cookbooks/basic_memory)

## 八、怎样评测记忆系统？

- 写入：有价值事实的提取精度与召回、误把临时要求写成长偏好的比例。
- 读取：Recall@k、排序质量，以及回答是否实际使用了正确记忆。
- 时效：新旧冲突、目标变化、计划变成已完成时能否正确更新。
- 删除：主记录、派生内容及同步后是否彻底失效。
- 隔离：跨用户、跨租户和权限变更后的可见性。
- 成本：检索与重排耗时、额外 tokens、存储增长、回退调用比例。

用一组多会话测试比较“无记忆”“全部历史”“经过筛选的记忆”，同时评估正确率、延迟和成本。检索命中不等于最终回答正确。

## 九、面试回答

我会用带版本、时间和来源的事实主记录维护生命周期，向量检索做候选召回，复杂关系按需用图谱，实时状态查业务系统。写入需提取、去重和冲突处理；读取先隔离用户与权限，再重排并核验有效性；删除要沿来源传播到摘要、索引与缓存。最后通过多会话任务和更新删除用例评估，而不是只看某次问答命中。
