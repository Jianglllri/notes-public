# GMP：多种违规共现与动态审核规则

> GMP: A Benchmark for Content Moderation under Co-occurring Violations and Dynamic Rules。arXiv 2026；本次未核实顶会录用。属于领域审核基准，不是 Agent 专用环境。

## 为什么二分类不够

一条内容可能同时包含多个违规点。只判断“有问题”无法确认是否完整识别，也不够支撑不同类别的处置、申诉说明与风险归因。另一个问题是规则变化：模型可能坚持预训练中习得的默认判断，没有遵循当前提供的规则。

## 论文事实

§3 给出3400个评测样本条目：Task A 1400条、Task B 2000条。Task A 测多标签违规识别；其中980条不安全样本，论文称81%的不安全样本存在共现违规。Task B 测四套动态规则下的判定，围绕 Action–Scope 表达组织规则。

两个子集从共同标注池抽样，因此不要未经检查就说是3400条互不重复的原始内容。数据构造含 LLM 增强、多个模型委员会标注及人工仲裁。

## Task A：Coverage Deficit

教学例子：金标是 {侮辱、身份偏见}，模型只识别侮辱。二分类正确，但规则解释不完整。Micro-F1 可以反映总体标签效果；Macro-F1 和逐类结果暴露长尾缺陷；覆盖相关指标检查共现标签遗漏。

“列出越多标签越好”也不对。无根据地添加标签会降低精确率并增加误杀。应同时检查命中、遗漏和多报。

## Task B：Policy Dynamism

论文用四套显式规则测试条件化判断，而不是让模型一直按默认偏好审核。其 default-permit 是实验任务约定，不能泛化成现实平台可以允许任何未列出的危险内容。

规则变化可以是类别、对象范围或场景变化，不只是总体变严格。因此 GMP 与 FlexBench 互补：后者强调严重程度阈值，前者强调具体规则组合。

## 从静态审核扩展到 Agent

实践建议：把 Task B 的政策直接给定改成“Agent 从政策库查找当前适用规则”，再测试选对版本、找到证据、应用规则、输出处置。这样增加了检索和流程难度，但也不再是原始 GMP 协议，必须另命名并描述变化。

增加三类测试：过期规则仍被检索到；多个规则优先级冲突；内容里包含伪装的审核指令。分别观察检索、规则理解和指令隔离，不把它们合成一个模糊错误标签。

## 局限与复现注意

委员会一致性不是客观真理；以模型分歧划难度会受所选模型影响。构造文本与真实用户表达之间存在分布差异。结构化输出失败也应计入系统可靠性，而不是静默丢掉后只报可解析样本。
