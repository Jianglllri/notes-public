# MT-AgentRisk / ToolShield：多轮交互为何放大风险

> ICML 2026。论文：Unsafer in Many Turns: Benchmarking and Defending Multi-Turn Safety Risks in Tool-Using Agents。本地版本 arXiv:2602.13379v2，2026-06-10；首页为 ICML 主会 PMLR 306。

## 核心问题

单轮任务中，有害意图可能很明显；在多轮中，准备、保存、引用、执行可以被拆开。只审当前一条消息的系统容易丢掉上下文和环境中的依赖。

论文 §3 由365个单轮任务构造多轮序列，涵盖五类工具：文件系统、浏览器、PostgreSQL、Notion、终端。图3显示序列为2–7轮，均值3.19轮。这里一轮指一次用户与 Agent 的交互，不等于一次工具调用。

## 分类法的学习重点

论文区分 Addition 与 Decomposition。前者增加间接层，使同一目标通过引用或包装表达；后者把目标分成多个子任务，组合后才形成完整含义。操作对象又分数据文件与环境状态。

学习时不必背攻击模板，应该理解“风险可能不在当前文本表面，而在它指向的内容以及执行后的状态”。例如，审核 Agent 批准了一个草稿引用，却没有读取引用对应的最新版本，就可能批准了不同于此前审核的内容。这是教学构造，不是原论文案例。

## 与 OpenAgentSafety 的区别

支持多轮交互，不等于专门测“分散的有害意图”。OpenAgentSafety 可以存在 NPC 多轮劝说；MT-AgentRisk 的构造目标是把原来的有害任务系统性地分布到多轮。读比较表时应注意作者对 multi-turn 的具体定义，不能简单说其他基准完全没有多轮。

## ToolShield 在做什么

防护方法利用 Agent 自身进行工具探索：生成测试案例、在沙箱执行、观察效果、提炼安全经验，再将经验用于部署。它不是只加一句“请注意安全”，也不是必须重新训练模型权重。

机制上的直觉是：工具文档描述功能，但经验可以补充“哪些上下文下会出问题”。然而经验质量受生成模型、沙箱覆盖和成本预算影响；没有发现的风险不会自动消失。

## 怎么设计可信实验

1. 对同一原始任务比较单轮与多轮，尽量保持最终目标不变。
2. 记录轮数、工具种类和每轮执行预算。
3. 失败要分成拒绝、工具异常、无能力完成和到达有害状态。
4. 防护还要在良性长任务上评估，防止它只是对复杂流程一概拒绝。
5. 经验库与测试任务隔离，避免把测试答案写进“安全经验”。

论文摘要的 ASR 改变量是该实验设置的汇总值。复现时需回到结果表确认百分比与百分点、单轮与多轮、平均方式，不可把摘要数字当作任意新系统上的保障。

## 面向内容审核的迁移建议

为每个被审核对象保存：对象 ID、内容哈希、规则版本、审核时间和证据。内容发生变化时重新审核；执行处置前重新核对对象与版本。把跨轮依赖加入评测：旧结论被复用、新内容未重审、引用内容不可见、规则切换未生效。

这些是受论文启发的防御实验设计，尚未在你的平台上实施或验证。
