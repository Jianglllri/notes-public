# AgentAuditor / ASSEBench：谁来评测安全评审器

> NeurIPS 2025 主会。论文：AgentAuditor: Human-level Safety and Security Evaluation for LLM Agents。

## 先区分方法与数据集

AgentAuditor 是提升 LLM 评审表现的记忆增强方法；ASSEBench 是评审器基准。输入主要是固定 Agent 交互记录，而不是让被测 Judge 在网站上执行任务。

§4 给出2293条独立交互：1476条 safety 与817条 security。Safety 的 Strict 和 Lenient 版本是在相同1476条记录上重新处理歧义标签，不能把三个1476和817相加，声称有5245条独立轨迹。整体覆盖15类风险、29类场景。

## 三阶段方法的直观解释

1. 从历史记录提取场景、风险、行为等结构化特征，形成特征记忆。
2. 选择代表案例，结合标注构造评审经验。
3. 对新轨迹按内容与特征检索相关案例，引导新的安全判断。

核心思想是让 Judge 参考相似的风险情境，不仅凭单一提示词判断。方法不要求重新训练权重，但仍有案例构建、检索、推理和存储成本。

## 为什么需要 Strict 与 Lenient

边界案例的争议不一定来自模型没读懂，有时来自对潜在风险的容忍度不同。若标注标准不明确，两个评审器可以给出相反标签，却各自符合一种合理口径。

因此需要明确：判定依据是已实现的危害、明确违规尝试，还是潜在风险？对于证据不完整的轨迹，如何处理？ASSEBench 的多口径设计提醒研究者把判定政策写进评测协议。

## “Human-level”应该怎样读

论文标题和实验声称达到与人类相近的评测表现。它不是“任意场景达到人类水平”，也不是“可以取消人工复核”。成立范围取决于数据集、标注协议、模型、指标与实验划分。

特别要检查：相似任务是否进入记忆库和测试集？记忆中的标签如何获得？检索是否泄漏测试答案？若把同一轨迹的不同改写拆到两边，可能高估泛化。

## 为审核 Agent 评审建立金标集（实践建议）

从明确安全、明确不安全、边界歧义、延迟拒绝、尝试失败、缺证据六类中采样。两名标注者独立判断，记录分歧，再由仲裁形成标签与理由。严重风险应单独统计漏判，不能被多数容易样本的高准确率掩盖。

让 Judge 输出简短证据引用、触发规则与结论即可；不必把冗长推理文本当作正确性的证据。最终需要与可验证日志和人工金标比较。

## 与 FlexBench 的区别

ASSEBench 判断“这段 Agent 交互安全不安全”；FlexBench 判断“这条内容在某种严格程度下是否违规”。前者面向行为轨迹，后者面向内容与口径。它们可以组成两层评测，但不可混合成一个没有解释的总分。
