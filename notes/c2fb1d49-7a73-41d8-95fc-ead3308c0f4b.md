# Deep Policy Research：让 Agent 写审核规则，如何评价质量

> Open-Domain Safety Policy Construction，EACL 2026 Findings。DPR 是方法，不是独立的通用 Agent benchmark。

## 研究问题与论文事实

人工维护审核规则成本高。DPR 输入一段领域说明，使用网页搜索迭代生成政策文档。§3 的流程包括提出查询、提取与合并规则、组织索引；规则强调条件、判断边界和适用范围。

作者在固定 reader 模型的前提下，仅改变提供的政策，观察下游审核效果。实验包括公开文本审核数据的五个领域，以及内部多模态广告审核集。后者不能默认完整公开可复现。

## 为什么不直接请 Judge 评价“规则写得好不好”

规则可能看起来完整、语言专业，但无法帮助实际审核。下游评估更直接：给同一个审核模型相同内容，只换政策，测分类是否改善。它把“规则写作质量”转化成可验证的使用效果。

仍要控制规则长度、检索预算和输入截断，否则改善可能来自更多上下文，而不仅是更好的策略构造。

## 论文结果应该怎样谨慎阅读

表1显示，在其固定设置中，DPR 相比 seed-only 的跨领域平均 F1 在两个 reader 上提升。但不能写成“每个类别都提升”：例如 Llama 的 Sexual 项，Seed为0.916、DPR为0.910；Qwen 的 Hate 项，Seed为0.817、DPR为0.811。这说明摘要式概括需要回到表格核对。

平均收益与局部回退可以同时存在。对于高风险业务，少量关键类别回退可能比整体平均提升更重要。

## 如何迁移到自己的审核流程

实践方案：先给定平台的正式政策与业务范围，再允许 Agent 检索补充解释或案例，输出带来源和版本的规则草案。人类审核后冻结版本，在固定审核器与锁定测试集上比较效果。

网页上的多数意见不能自动成为平台政策。来源质量、权威性、适用地域、有效期与冲突处理都应进入规则审查。该笔记不把法律合规问题简化成搜索结果投票。

## 对照实验应包括什么

1. 只有简短领域定义。
2. 固定数量的人工案例。
3. 人工编写政策。
4. Agent 生成政策。
5. 同预算但无规则合并 / 无索引的消融。

固定 reader、数据划分、阈值和评测方式。对每个领域记录提升与回退，再抽查改变的判定是否有正确依据。

## 关键局限

搜索结果随时间变化，必须保存证据和检索时间；政策可能包含偏差；同一政策对不同 reader 的效果不同；内部广告数据限制外部验证。文本审核有效也不能直接推断图像或短视频审核有效。
