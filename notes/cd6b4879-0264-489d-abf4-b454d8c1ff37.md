# Jev 与语义判断模型学习指南｜开源、闭源与 Agent 记忆应用

调研日期：2026-11-02。范围：快速语义判断、分类、路由、重排和抽取；不是通用聊天模型排行榜。依据官方文档、模型卡与研究论文整理，未调用付费模型、下载权重或实测性能。版本信息是本次查询快照，厂商 benchmark 不当作自己的实验结果。

## 一、先理解问题：一定要让模型“写一段话”吗？

假设收到一句：“我已经问过三次了，请找个人处理退款。”应用真正需要的可能是三个结果：是否退款请求、是否要求人工、属于哪个业务队列。无需先生成长解释，再从解释里解析字段。

语义判断模型把任务压缩成受约束的选择或打分。普通代码负责精确规则、数据查询和执行，模型处理“字面规则难以覆盖的含义”。它仍会判断错：输出类型合法不等于语义正确。

学习时分四类：通用判断模型（Jev、GLiClass）、相关性重排模型（Qwen/Cohere/Voyage Rerank）、实体与结构抽取模型（GLiNER）、能生成解释与代码的通用 LLM。任务有交集，但不是无损替代关系。

## 二、Jev 是什么？

Jev 是 TypeSafe 的托管 System One 判断模型，输入 state 和有明确答案空间的问题，返回类型化结果和概率，不负责生成长文章或推理解释。“System One”是其产品与方法定位，不是大脑机制或某一种 Transformer 结构的证明。[官方概念](https://docs.typesafe.ai/concepts/system-one)

截至调研日，官方最新稳定版本为 **jev-1.14.0**（2026-10-14 发布），jev-latest 与 jev-preview 均指向它。默认每请求 64k、state 加任一问题 32k；官方另提供可选 262k 长上下文模式并提示速度与准确率代价。标价为每百万输入 token 0.042 美元，输出免费。固定版本便于复现实验；中文效果需要单独测试。[模型与限制](https://docs.typesafe.ai/models)

Jev 按商业托管服务理解；本次未找到官方开放权重，不应把 SDK/示例开源理解为模型权重开源，也不猜测未公开的参数规模与内部网络结构。

### Choice：互斥选项中选一个

例如队列为 billing、technical、account、no_match。选项应定义清楚，并留出不匹配情况。若退款和投诉可以同时成立，应分别做多个二值判断，而不是强迫只选其一。[Choice 文档](https://docs.typesafe.ai/primitives/choice)

### Noul：一个条件成立的概率

例如“用户是否明确要求人工”。返回 P(yes)，不是严重程度；0.5 表示 yes/no 不分明，不代表“中等程度地要求人工”。它没有另一个 Choice 式 confidence 字段。[Noul 文档](https://docs.typesafe.ai/primitives/noul)

### Score：有序等级上的位置

定义三档：0=无相关信息，1=提供部分线索，2=足以直接回答。若教学分布为 [0.1,0.3,0.6]，期望位置为 0×0.1+1×0.3+2×0.6=1.5。等级必须能独立解释，混合“相关性、可信度、时效性”为一个模糊分数会使诊断困难，应拆开评估。[Score 文档](https://docs.typesafe.ai/primitives/score)

### 图像与 Box：预览能力，不要写成全面稳定支持

当前 Box 专页说明可通过实验 header 使用图像定位，返回归一化坐标，仍未达到官方生产就绪标准。概念总览还写着 text-only，与新专页存在更新不同步；学习时区分默认文本能力和明确启用的图像预览。[Box 专页](https://docs.typesafe.ai/primitives/box)

## 三、概率、confidence 和校准要分开

Choice/Score 的 confidence 根据输出分布的集中程度计算，是分布统计量，不是该次回答正确的保证；Noul 则直接使用二值概率。[Confidence 文档](https://docs.typesafe.ai/confidence)

校准的直觉：预测概率约 0.8 的大量案例，在对应数据分布上应有约 80% 命中。一个模型可以非常自信地犯错；一个领域上校准良好，不代表换语言、换候选标签或换业务后仍成立。

教学例子：A 的两类分布 [0.95,0.05]，B 为 [0.52,0.48]，A 更集中；但如果真实标签是第二类，A 仍然错得很自信。不要把“返回了 0 到 1 的数”视为已完成校准。

实际设置：用标注验证集选阈值，记录自动处理覆盖率与错误率；不确定案例交给更强模型、补查证据或人工。阈值不是固定的 0.5/0.8，对不同任务分别优化。模型分数也不构成业务权限或执行授权。

## 四、最新开源方向：GLiClass v4

### GLiClass v4 Edge：最适合先理解判断模型

官方模型卡的 `knowledgator/gliclass-v4-edge` 是约 0.4B 编码器，Apache-2.0，输入文本、候选标签和可选指令，单次前向给各标签打分，不生成文本。适合本地分类、路由和内容筛选。模型卡以英语为主；中文需独立验证。[模型卡](https://huggingface.co/knowledgator/gliclass-v4-edge)

学习重点是“标签由调用者提供”与“动态候选集”，以及单标签、多标签和重排如何使用不同输出语义。模型卡中的速度、排行榜来自其测试口径，不能与另一厂商 API 的网络端到端时延直接横比。

### GLiClass v4 2B：理解生成式骨干如何变成判断器

`knowledgator/gliclass-v4-2b` 提供 Apache-2.0 权重，支持多模态判断。官方描述以 Qwen3.5-2B 编码输入至 KV cache，再让标签表示读取该状态并进行评分；还使用有限步的标签状态迭代。它不以生成长文字作为输出。[模型卡](https://huggingface.co/knowledgator/gliclass-v4-2b)

特别注意模型卡说该 checkpoint 没有附带事后校准器，原始分数常接近 0/1。不能看到极端分数就当成高度可靠的业务概率。它与 Edge 的骨干、延迟和任务优势不同，也不能只凭参数更大宣布全面更优。

官方系列还列出 9B、27B 版本，本指南优先学习 Edge 与 2B，不扩成大模型清单。[官方模型列表](https://huggingface.co/knowledgator/models)

## 五、开源抽取方向：GLiNER2.5

`fastino/gliner2.5-multi-v1` 为约 287M 的多语言 schema 驱动抽取模型，Apache-2.0。当前官方仓库区分旧版 span 架构与 2.5 的 boundary 架构，可处理实体、分类、结构化记录、关系等任务；读取任意系列 checkpoint 时应遵循相应加载器说明。[官方仓库](https://github.com/fastino-ai/GLiNER2)、[模型卡](https://huggingface.co/fastino/gliner2.5-multi-v1)

例如“我下个月开始学 CUDA”，可以抽取技能 CUDA 和时间表达“下个月”，但不能自动把它记成“已掌握 CUDA”。抽取后的时态、否定、身份与事实状态仍要核验。

它与 Jev 的关系：GLiNER 更适合“从原文取出哪些字段”，Jev/GLiClass 更适合“这句话或候选应如何判断”。抽取模型也支持分类，但能力交集不意味着所有问题都等价。

## 六、开源重排方向：Qwen3-Reranker

Qwen3-Reranker 有 0.6B、4B、8B，0.6B 官方卡提供 Apache-2.0 权重、32k 上下文及多语言支持。主要任务是输入 query 与 document，输出相关性分数，可用于向量/BM25 召回后的第二阶段排序。[官方模型卡](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)

它不是 embedding 模型：embedding 可离线编码海量文档并快速召回，reranker 通常联合处理查询与候选，适合精排较少候选。Qwen 官方实现利用 yes/no 的打分；即使经过 sigmoid 得到 0–1，也不能自动理解为业务正确率。

学习建议：先看懂“召回 top-50 → rerank → 选 top-5”，再理解怎样用任务指令调整相关性。这个系列是本次核验的成熟开源学习基线，不宣称它是所有开源重排模型中的最新或最强。

## 七、闭源专用模型：Cohere 与 Voyage

### Cohere Rerank 5

官方当前系列为 `rerank-v5.0-pro` 与 `rerank-v5.0-fast`，前者侧重质量，后者侧重延迟和吞吐；提供 32k 上下文、多语言、相关性评分及 Context Focus 相关片段定位。架构为专有；托管或私有部署不等于开放权重。[官方文档](https://docs.cohere.com/docs/rerank)

与 Jev 比较时，只在共同任务（例如 query-document 相关性）上比较。Rerank 不是一般意义的任务规划器。官方宣称分数校准，也仍需在自己的中文数据、阈值和负例上验证。

### Voyage Rerank 3

官方当前推荐 `rerank-3` 与 `rerank-3-lite`，32k，区分质量优先与时延/成本优先；输入查询与候选文档，输出排序和分数。官方目录仍列旧版 2.5，但不能据旧教程把 2.5 当成最新。[官方文档](https://docs.voyageai.com/docs/reranker)

闭源服务的学习重点是输入契约、批量限制、截断行为、端到端延迟和计费口径，而不是试图猜测隐藏网络细节。本次未做 API 实测。

## 八、为什么还要保留通用 LLM 基线？

通用 LLM 配合结构化输出也能分类、打分和抽取，并可生成解释、摘要或代码。判断模型在受约束任务上有机会更省延迟和费用；通用 LLM 对开放任务、复杂计划和长文本生成仍有价值。

区别不在“返回的是不是 JSON”，而在模型训练目标、推理路径、输出空间、概率含义和真实任务性能。对比时给各模型相同证据与候选，避免让某个模型额外看到答案；若要求解释，应单独统计解释成本，不能把纯判断接口与生成长推理的调用直接比较。

本次阅读的一项 2026-10-29 更新的外部研究，针对 **Jev 1.13** 测试了分类、路由等任务，并与 Qwen3.8-27B、Gemma-4-E4B 比较。研究报告其判断任务表现较好，但部分连续行动环境中 Qwen 的任务完成率更高，也观察到无效动作重复。它支持“单步判断准确不等于长程规划成功”，不能直接当作 Jev 1.14 的成绩。[研究论文](https://arxiv.org/abs/2609.37647)

## 九、把这些模型接入长期记忆：一个可学习的方案

下面是教学设计，不是已经部署的功能。

1. 数据库保存当前用户、原消息、时间、授权范围和记忆版本。
2. GLiNER 或其他抽取器提取候选事实、实体、时间；保留原文证据。
3. Jev/GLiClass 判断“稳定偏好还是临时要求”“是否与同范围旧记录冲突”。
4. 普通代码决定新增、替代、保留历史或不写入；不是模型分数一高就删除旧记忆。
5. 新请求先过滤身份和有效状态，再用 embedding/BM25 召回。
6. Qwen/Cohere/Voyage Rerank 或经过验证的 Jev Score 对候选排序。
7. 通用 LLM 根据精选记忆生成回答，必要时指出缺少信息。

TypeSafe 的官方简单记忆示例也明确要求由应用在后续 state 中加入历史，模型不会自动记得上一请求。其示例基于小型构造工单集和 Python dict，只适合理解机制，不能直接当作生产记忆方案。[官方示例](https://docs.typesafe.ai/cookbooks/basic_memory)

## 十、用一组实验学会选型

建议先整理 100–200 条中文教学样本，包含：稳定偏好、临时约束、否定、目标变化、相同词不同含义、缺失候选、完全无关内容。划分验证集与独立测试集，阈值只在验证集调整。

- 分类/路由：accuracy、macro-F1、多标签 precision/recall，检查不匹配选项。
- 抽取：实体或字段级 F1、来源跨度正确性、否定与时间条件是否保留。
- 重排：Recall@k、MRR/nDCG，以及下游回答质量。
- 概率：Brier score、校准曲线，以及不同自动处理覆盖率下的错误率。
- 工程：同一输入规模、候选数、并发下的 p50/p95、失败重试率和总费用；本地模型记录硬件、精度、batch、冷启动，API 记录网络耗时。

Brier 二值示例：真实 y=1，预测 p=0.8，平方误差为 (0.8−1)²=0.04。不能只挑几条看起来正确的案例证明模型整体校准。

不需要下载所有模型。先用规则和现成模型建立基线，再比较一个本地判断器、一个托管判断器和一个重排器。模型卡公开权重只意味着具备部署条件，具体许可、依赖和中文效果仍分别检查。

## 十一、建议学习顺序与面试答法

第一步学 Choice/Noul/Score 和概率校准；第二步学 GLiClass 的动态标签分类；第三步学 GLiNER 的字段抽取；第四步学 embedding 与 reranker 的区别；第五步组合记忆写入、查询、更新与删除闭环。

面试回答：Jev 是面向受约束语义判断的托管模型，输出选择、等级和二值概率。类似需求可以用开源 GLiClass、抽取专用 GLiNER 或重排专用 Qwen 系列实现不同子任务；闭源 Cohere/Voyage 专注重排，通用 LLM 适合生成与复杂规划。不能把格式正确当成事实正确，也不能把分数当成未经验证的正确率。最终要在同样的数据和任务口径上比较质量、校准、延迟、费用和部署约束。
