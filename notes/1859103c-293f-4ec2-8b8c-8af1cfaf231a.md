# Agent 内容安全评测：学习导航

> 整理日期：2026-10-21。范围：此前检索到的 10 篇论文，以 2025–2026 为主，附 2024 基础工作。已核读本地 PDF 的研究问题、基准设计与主要评测章节；不是穷尽文献综述，也没有实际运行这些 benchmark。

## 学完这个专题，你应该能够做什么

1. 分清“被评测的 Agent 会不会造成内容风险”和“内容审核 Agent 判得准不准”。
2. 看懂样本、交互轨迹、环境状态、评测器四者之间的关系。
3. 判断一篇论文的分数是否真的证明了安全，而不是模型能力不足、过度拒答或评测器漏判。
4. 为中文内容审核业务设计一套包含分类、规则理解、工具执行和端到端结果的评测。
5. 能向同事解释为什么不能只用一个 ASR 或 F1 排名。

## 两条主线，先选你的问题

**主线 A：评测 Agent 的内容安全。** 用户让 Agent 写文章、发布评论、转发内容或管理社区时，它会不会生成或传播不安全内容？优先读 SafeArena、AgentHarm、MT-AgentRisk，再读 OpenAgentSafety 和 ST-WebAgentBench。

**主线 B：评测内容安全审核 Agent。** Agent 本身是审核员，它需要查规则、取证、分类、解释、升级人工或执行处置。优先读 FlexBench、GMP、Deep Policy Research；若要评测“审查其他 Agent 轨迹”的 Judge，再读 ASSEBench。

这两条线可以组合。例如，审核 Agent 正确识别了有害评论，但错误地删除了另一条评论：分类正确，流程仍然失败。

## 建议的四次学习安排

### 第一次：建立概念，约 60–90 分钟

读 01、02、03、04。写出你业务中的一个安全任务与一个有害任务，要求两者调用相同工具、路径难度接近。解释为什么必须同时测它们。

### 第二次：从单轮走向轨迹，约 60–90 分钟

读 05、06、07、08。画出一条完整轨迹：用户请求 → 工具观察 → Agent 动作 → 环境变化。指出哪一步首次越界，以及最终结果是否成功。

### 第三次：审核员也需要评测，约 60–90 分钟

读 09、10、11、12。区分“规则生成质量”“审核决策质量”和“审核流程质量”。为一个边界内容写两个不同审核口径下的标签。

### 第四次：做自己的小实验，约 90–120 分钟

按 13、14 设计试验，不必先部署所有环境。先造 12 个虚构案例，人工标注，再完成静态分类和轨迹审核；最后用 15 自测。

## 如何理解本专题中的证据

- **论文事实**：给出来源、章节或表格；数字只适用于论文指定版本和实验设置。
- **学习解释**：为了理解而做的通俗重述或虚构例子，不是原文案例。
- **实践建议**：本专题综合提出的设计方案，不是已有 benchmark 的官方协议或经过验证的新结果。
- **待核实**：没有可靠录用记录、没有检查公开数据权限或没有实际复现时会明确标注。
