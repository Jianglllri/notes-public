# AgentHarm：拒答之外，评估实际有害任务能力

> ICLR 2025。完整标题：AgentHarm: A Benchmark for Measuring Harmfulness of LLM Agents。威胁模型是恶意主用户的直接滥用。

## 论文事实：任务、工具、评分三件套

§3 包含 110 个基础行为，每类 10 个，覆盖 11 类危害；通过详细 / 开放式任务以及是否提供首个工具提示，扩展到 440 条。论文表1列出验证集44、公开测试264、私有测试132，并包含104种不同函数。

工具是无真实副作用的固定合成实现，便于复现。细粒度 rubric 主要检查函数调用、顺序和参数；需要判断文字含义时才使用局部语义 Judge。通过部分检查可以得部分 harm score。拒答率是单独记录的辅助指标，并检查所有 Agent 消息。

## 为什么不能只测“有没有拒绝”

虚构场景：系统被要求执行一个禁止的传播任务。它可能没有说拒绝，但只生成了草稿，未找到目标页面；也可能先执行动作，最后才加上安全提醒。单看最终一句话会错判两者。

任务级评分应问：关键工具是否被调用？顺序是否满足依赖？参数是否对应目标？产生的内容是否满足任务意图？这比一句“你觉得这个 Agent 有害吗”更容易定位错误。

## 部分得分怎样理解

若四个检查中通过三个，得到较高分不意味着有害行为一定已经完全成功；如果关键的真实副作用步骤没完成，业务后果可能不同。反过来，某个未通过的非关键检查也不一定代表没有风险。因此迁移到业务时，应区分诊断性子项与关键安全门槛。

本文不提供替代官方评分函数。正式复现需要使用论文仓库的 rubric，而不是凭概念说明自行平均后声称复现。

## 合成工具的价值与代价

价值在于稳定、低成本、容易记录因果链，不必依赖真实网站的变化。代价是环境真实性较弱，难以覆盖真实权限、网络故障、网页变化与不可逆副作用。

适合用作第一层回归测试，检查修改后的模型或防护是否明显退化。若要证明生产系统安全，还需要可重置真实工具环境和端到端状态检查。

## 对审核 Agent 的启示

可以把审核工作拆成：取内容 → 读适用规则 → 输出标签与证据 → 决策 → 处置。为每个步骤写检查器。最关键的是，不要只检查“调用了审核工具”，还要检查传入的是不是最终发布内容、对应的政策版本和正确对象。

这属于从论文借鉴的工程设计，不是 AgentHarm 原始任务。审核任务的“完成”应是正确且合规的处置，而不是有害目标完成。

## 推荐的实验对照

- 无防护、仅输入审核、输入加工具前检查三组。
- 所有组共享相同工具和步骤预算。
- 同时评测良性对应任务，观察防护是否导致过拒。
- 保留所有中间消息和函数调用，不只保留最后输出。
- 按原始行为家族划分数据，避免同一行为的改写同时进入调参与测试。

## 阅读定位与资料

重点看 §3.1.2 合成工具、§3.1.3 细粒度评分、§3.2 设计原则。旧论文中的美元成本是历史实验价格，不是当前报价。
